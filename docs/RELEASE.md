# Подключение, выпуск и откат

Текущая облачная копия: `Slime Salvage [Test]`, universe `10773715101`,
выбранный пользовательский владелец `Masssha1337`. Studio импортировал сцену;
Play не запускался. Data Sharing оставлен включённым по явному выбору пользователя.
Dashboard: https://create.roblox.com/dashboard/creations/experiences/10773715101/game-details
Приватность, вместимость, API services и доступ к аудио пока не подтверждены.

## До игровых тестов

1. Установить Roblox Studio из официального источника. Под владельцем проекта создать
   отдельный **приватный** Test experience. Открыть собранный .rbxlx и сохранить туда.
2. Проверить в BuildConfig: environment=`Test`, persistenceEnabled=true,
   monetizationEnabled=false. В настройках приватного Test разрешить Studio API services.
   Не подключать Studio к Production DataStore; код запрещает такое сочетание.
3. Настроить максимальный сервер на 8 игроков. Публичный experience и его namespace
   должны быть отдельными; номера place/universe записать в выпускной журнал.
4. Загрузить assets/audio/*.wav под тем же владельцем, дать Test experience доступ
   к аудио. Указать реальные `rbxassetid://...` в BuildConfig.audio, пересобрать место.
   Пустые строки не считаются подключённым звуком.
5. Проверить настройки публикации, право автора на материалы, мобильный формат,
   текущие требования Roblox и анкету контента. Платёжный каталог оставляем отключённым.

Без аккаунта/приватного experience эти действия нельзя заменить выдуманными ID.

## После завершения реализации и подключения

Пройти ACCEPTANCE.md. Каждый результат содержит SHA сборки, версии баланса/схемы,
устройство, число клиентов и доказательства. Провести минимум 5 наблюдаемых
прохождений, затем проверить время открытия островов и скорректировать конфигурацию.
Пользовательские игровые тесты не объявляются начатыми только из-за запуска Luau CLI.

Обязательно проверить настоящий DataStore: два сервера, потеря ответа, отказ записи,
закрытие сервера и восстановление. Автотест Lease проверяет нашу логику,
но не сетевые гарантии Roblox и не настройки аккаунта.

## Сохранения и поддержка

Namespace: `SlimeSalvage_Test_v1`, `SlimeSalvage_Beta_v1`, `SlimeSalvage_Production_v1`.
Поддерживается schemaVersion=1; будущая версия отклоняется без перезаписи. Формат
предыдущего временного среза не записывался в DataStore и не мигрируется как реальный профиль.
Перед будущей миграцией сохранить версию кода и выборку копий тестовых профилей;
только после теста на копиях включать миграцию. Использовать историю версий DataStore
для разбора повреждений; не исправлять массово данные без резервной копии.

Обычная добыча сохраняется каждые 50–70 секунд и при нормальном выходе. Авария Roblox
может откатить неподтверждённую добычу; абсолютное отсутствие отката не обещается.
Критическая мутация подтверждается после сохранения одного профиля целиком. Неизвестный
результат записи блокирует дальнейшую экономику, ограниченно перепроверяется с тем же
writeId и тем же результатом; затем предлагается переподключение.

## Публичный выпуск

После закрытия Blocker/Critical: подготовить честную иконку и 3 обложки из реального
геймплея, описание, способ обратной связи, маленький следующий апдейт, журнал
известных ограничений. Записать SHA, balanceVersion, schemaVersion, настройки,
asset ID, Test/Public place ID. Поставить тег только принятой сборке.
Платёжный каталог остаётся выключенным, пока отдельная серверная выдача, реальный
каталог и receipt-тесты не реализованы/проверены. Выпуск бесплатной беты допустим по S-03.

## Откат

Выключить randomOperationsEnabled при проблеме случайных операций; платежи всегда
выключены в этой версии. Опубликовать последнюю совместимую проверенную сборку,
перезапустить серверы через Dashboard. Не откатываться на код, который читает
неподдерживаемую schemaVersion как новый пустой профиль. Не сбрасывать DataStore
ради исправления клиентской ошибки.
