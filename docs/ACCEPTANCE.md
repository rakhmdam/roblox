# Slime Salvage — приёмка беты 0.1

Приложение к [ТЗ](TECHNICAL_SPEC.md). Наличие теста в списке не означает, что он уже выполнен. Каждый прогон фиксирует build/tag, balanceVersion, schemaVersion, устройство, число клиентов, результат и доказательство (лог/видео/снимок).

## 1. Уровни ошибок

- Blocker: потеря/повреждение данных, невозможность входа, массовый crash, неконтролируемое списание/дублирование покупок.
- Critical: обход островов/владения, дублирование валюты, непреодолимый стоп обучения, неработающий основной путь телефона.
- Major: существенная поломка функции с обходным путём, серьёзные просадки производительности.
- Minor: косметическое несовпадение без препятствия игровому действию.

Для публичной беты: 0 известных Blocker/Critical, Major на основном цикле устранены; прочие задокументированы с решением о выпуске. Ограничение финансового каталога не маскирует неисправную обработку платежей: при отсутствии проверки каталог выключен.

## 3. Экономические и негативные тесты

- QA-24 / NET: подделать price/damage/wallet, node чужого игрока, закрытый islandId, неизвестный recipeId. Нет изменения профиля, возвращается проверяемый errorCode.
- QA-25 / NET: NaN, Infinity, отрицательные/дробные количества, невалидный UTF-8, слишком большие строки/списки, повтор UID. Нет ошибки сервера или частичного применения.
- QA-26 / NET: 100 запросов в секунду в течение 10 секунд от тестового клиента. Ограничение частоты действует, другим игрокам доступна игра. Тест только в отдельном закрытом окружении.
- QA-27 / NET/L: выбор цели вне дальности, сквозь препятствие, во время смерти, меню, перехода и без доступа к острову. Урон/награда не начисляются.
- QA-28 / E: кошелёк/материал около лимита, переработка/событие переполняет его. Операция целиком отклонена до списания или уничтожения, нет молчаливой потери награды.
- QA-29 / E/P: craft → recycle и rank/level → recycle. Нет положительного цикла монет/фрагментов; цена/возврат совпадают с конфигурацией.
- QA-30 / NET/D: ответы с ревизиями пришли в обратном порядке. UI не откатывает кошелёк и команду к старому состоянию.

## 4. Сохранения и отказоустойчивость

- QA-31: нормальный выход/вход, смерть, путешествие, покупка, инкубация. Восстановлены все обязательные поля D-01, включая cargo и tutorial, а временные цели сброшены.
- QA-32: Get/UpdateAsync возвращает ошибку, throttling и timeout. Есть ограниченные повторы и понятное ожидание; существующий профиль не становится новым.
- QA-33: два сервера одновременно запрашивают один тестовый профиль. Только одна активная lease; при её потере старый сервер не пишет поверх нового.
- QA-34: отказ сохранения сразу после определения RNG-исхода, повтор UpdateAsync callback. Не возникает новый исход; неподтверждённая операция не даёт отдельно сохранённого списания.
- QA-35: аварийное завершение без финального сохранения. Обычная добыча может откатиться в заявленных пределах; подтверждённые критические операции присутствуют целиком.
- QA-36: один requestId повторён в текущей сессии и в старой с новым sessionNonce. Первый не дублируется, устаревший отвергается.
- QA-37: миграции каждой поддерживаемой schemaVersion и неизвестная будущая версия. Сохраняется валидное владение; несовместимый профиль не перезаписывается.
- QA-38: test/production namespace. Studio и тестовые админ-команды не могут писать в Production; тестовые данные и функции не попадают в публичную сборку.

## 5. Вероятности и арифметика

Модульные тесты обязательны для кошелька/транзакций, гарантий, цен, командных лимитов, эволюций и миграций. Они вызывают доменную логику, а не копируют ту же формулу в тесте без независимых примеров.

- QA-39: сумма весов каждой полной таблицы равна 10 000; все speciesId существуют; цены/уровни/награды конечны и неотрицательны.
- QA-40: контролируемый RNG выдаёт каждую границу интервала весов; невозможные исходы гарантии не выбираются. Счётчики проверены на длинных последовательностях.
- QA-41: распределение обычных инкубаторных бросков на 100 000 попыток с фиксированным seed сопоставляется базовым весам отдельно от гарантии. При тесте с гарантией сравнивается соответствующая модель, не исходные 55/27/12/5/1.
- QA-42: контрольные примеры BALANCE.md (72 монеты за 12 предметов; 39−30=9 после учебного улучшения), реальные расходы/остатки сверены с серверным состоянием.
- QA-43: максимум level/rank/evolution/trait/tea/aura. Бонусы не складываются сверх ограничений, Collector/Breaker/Sweeper/Support ведут себя по спецификации.

- QA-50: при выключенном monetization flag отсутствуют покупочные prompts и активные ложные кнопки. При включённом — реальный каталог, серверная выдача, сохранение cosmetic entitlement.
- QA-51: если есть Developer Product, повторить receipt с тем же PurchaseId, временную ошибку хранилища и повторный вход. Право выдаётся один раз; отказ сохранения не подтверждается как обработанная покупка.
- QA-52: убедиться, что монеты/попытки/шансы/добыча не приобретаются за Robux прямо или косвенно в каталоге 0.1; будущая смена схемы требует отдельной проверки PolicyService и вероятностей.
- QA-53: выключение feature flag случайных операций и безопасный откат. Профиль новой схемы не становится пустым при старой сборке.
- QA-54: сверить asset manifest, настройки публикации, анкеты, 3 обложки, описание и известные ограничения. Визуальные материалы соответствуют игре.

## 8. Наблюдение за игроками

Для первого среза 5–10 человек вне разработки: дать цель «поиграй» без инструкций; записать первый выбор, затруднения и причины выхода. Для альфы стремиться к 20–50 тестировщикам, если получится привлечь бесплатно. Отдельно учитывать телефон/ПК, прошедших обучение и пропустивших его.

Проверить контрольные времена BALANCE.md и три стратегии расходов. Процент удержания не объявляется достоверным при маленькой выборке. Решение о следующем контенте опирается на наблюдения: если люди не понимают сбор/продажу или не хотят продолжить, исправляем первую зону до выпуска остальных.
